## 当前接续

更新：2026-11-10。这里只保留最新接续状态，详细事实与依据由上方主题文件维护。

- **当前重点（已确认）**：当前阶段使用 C++ 标准库实现日志，公共接口只使用 Namica/标准类型；保留 LogRecord/LogSink 分离，将整行布局和最低等级迁移至输出端，暂不开发多线程日志，见 [项目决定](DECISIONS.md#已确认)。文本输出端由 TextSink 统一布局与日期格式，ConsoleSink 和 FileSink 共享 `setLogFmt`/`setDateFmt`/`formatRecord`；布局为 `{0}` 时间、`{1}` 等级、`{2}` 来源、`{3}` 正文。
- **实现进度**：FileSink 已接入 Core/App 共享输出，日志测试现有 53 项，包含新增 17 项 FileSink 专项与 3 项 Log 集成测试。已审核 runtime 全部 117 项用例声明的注释（含原有 3 项禁用）；Debug 构建及启用的日志 53/53、数学 61/61 回归通过，详见 [PROJECT](PROJECT.md)。
- **停留位置**：单测注释、utils 归属、格式化与 Git 提交/署名规则集中在 AGENTS。日志辅助归入 log/utils，数学比较归入 math/utils；runtime/utils 仅保留公用夹具。构建依赖已确认模块工具各自只进入对应测试目标；断言与禁用状态保持不变，未修改运行时代码或 CMake。文件运行期 I/O 故障注入及其他覆盖边界见 PROJECT；逐条开关及后续增量扩展见 [刷新策略与兼容边界](ARCHITECTURE.md#文件刷新策略与接口稳定性待讨论)。
- **下一步（建议，未授权实施）**：按实际需求继续日志功能；周期调度等到主循环具备维护阶段时接入。Logger 错误收集、初始化回滚、析构失败边界与真实控制台编码仍按后续阶段处理，FileSystem 接口兼容和发布目录策略仍需留意。
