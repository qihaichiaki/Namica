# Namica 项目知识库

最后整理：2026-11-01（Asia/Shanghai）。

这份知识库由用户要求建立，供后续 agent 接续项目指导。它总结当前代码、用户目标、讨论中的决定与建议；不是代码迁移任务单，也不是已实现功能清单。

## 快速接手

- **身份：引擎开发老师与顾问。** 默认给讲解、分析、审阅和建议，未经明确授权不改项目代码。详细规则见 [AGENTS.md](AGENTS.md)。
- **目标：** 长期建设个人实用引擎；[当前日记](../doc/life/梦醒再梦.md) 已将第一阶段定为贪吃蛇的编辑器操作到简化打包、独立发布流程。
- **已确认边界：** runtime、tooling、editor 顶层分离，tooling 独立构建。
- **设计偏好：** 参考成熟引擎的实际组织；先讲清长期结构与原理，当前仅实现其中部分可用功能，不用当前简化方案替代长期规划。同时反对过早细分成大量路径类、加载器类和构建层次。
- **建议前置条件：** 每次提出引擎开发建议前，先核对相关成熟引擎的官方文档或源码，提供来源并区分参考事实与 Namica 的适配建议；不能凭空设想。完整要求见 [AGENTS.md](AGENTS.md#建议必须有成熟引擎依据)。
- **当前阶段：** C++20 / Windows / CMake；编辑器仍是入口占位，大量渲染功能在 playground。HEAD 为 8a4e593，已有同步 Logger，Log.h 仍为空。用户已完善 setLogFmt 的 Bool 返回及设置时校验，移除 nodiscard/noexcept；授权补测后，core/TestLog.cpp 新增 4 项、合计 17 项 Logger 测试全部通过。覆盖有效/无效布局、失败保留旧值、后续配置恢复及字符串生命周期；独立 compile 目录和目标已移除。消息提交失败策略仍待定。详情见 PROJECT。
- **没有当前默认的代码实施授权。** 先回应用户当下问题，不自动执行知识库中的迁移建议。
- **测试前先同步接口。** 用户要求先说明公开接口与长期规划是否一致，区分稳定行为与待定策略，再增加测试；本轮日志测试授权不扩展到实现修复。

## 持续维护方式

1. 用户明确作出选择或纠正：更新 `DECISIONS.md`，并修订受到影响的建议。
2. 阅读源码发现实现变化：核实后更新 `PROJECT.md`，记录检查日期和证据路径。
3. 形成新方案：写入 `ARCHITECTURE.md`，记录相关成熟引擎依据、版本或提交（已知时）、核对日期与适配取舍，明确标成建议；只有用户确认后才升级为已确认决定。
4. 执行过验证才记录具体结果；记录日期和范围。仅提供命令不等于执行过验证。
5. 尽量更新现有主题，避免每轮聊天新增一个文件。重大取舍可以留短记录，不保存整段聊天。
6. 对源代码与文档的冲突，先指出差异；不要为了让代码符合知识库而自动改代码。

维护发生在后续实际交流和工作中，没有创建后台定时任务。
