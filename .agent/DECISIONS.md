# 当前项目决定

整理：2026-11-03。这里只保留影响后续开发的项目选择；操作与协作规则见 [AGENTS.md](AGENTS.md)。

## 已确认

| 事项 | 当前约定 |
| --- | --- |
| 长期目标 | 建设参考成熟引擎设计、可实际使用和持续演进的个人游戏引擎 |
| 第一阶段 | 用贪吃蛇打通编辑器操作、保存、试玩、简化打包和独立运行；具体可编辑范围尚未确定 |
| 顶层分工 | runtime 提供游戏运行能力；tooling 为独立顶层目录和构建目标；editor 使用二者，正式游戏通常不链接 tooling |
| 当前重点 | 继续开发 Log；具体接口、输出后端及实现顺序需逐步收敛 |
| 日志布局失败 | 保留 `setLogFmt` 名称，使用显式失败结果；无效布局保持旧配置，已实现状态与测试见 PROJECT |
| 日志使用前提 | Log 强依赖 Application 初始化；未创建并完成初始化时调用 Log 不受支持，用户不直接调用私有 init。输出资源关闭与失败诊断细节仍待讨论 |
| 日志编译裁剪 | NAMICA_LOG_DEBUG 控制 Trace/Debug 便捷宏；DLL 与调用方分别定义自己的开关，PRIVATE 不向调用方传播是预期行为，调用方开关不能改变已编译的 DLL。关闭分支移除调用与参数求值，当前实现见 PROJECT |
| 异常机制 | 接受 C++ 异常用于少量特殊失败，不作为常规流程控制；具体异常类型与捕获边界仍待细化 |
| 数学容差 | `NAMICA_TOL` 的位置、名称和值暂时保持，仅在实际涉及容差策略时再讨论 |

阶段目标来源：[项目日记](../doc/life/梦醒再梦.md)。

## 仍需决定

- **日志**：记录与输出接口、后端选择、Core/App 之外的来源表达、初始化失败回滚和关闭协议、消息/输出失败策略、并发范围、各构建目标的日志开关默认值与运行期配置。
- **游戏制作流程**：最小编辑能力与验收内容、场景和资源数据格式、资源 ID、游戏逻辑接入方式。
- **系统演进**：[Application 应用框架](ARCHITECTURE.md#application-与运行库待讨论)的完整职责与配置、tooling 的库形式、窗口和渲染实验的正式接口、编辑器 UI，以及是否需要 ECS、脚本、反射或热重载。
- **所有权策略**：各系统如何持有和销毁对象、借用引用的有效期，是否需要创建入口、池或句柄；尚未形成全局内存管理方案，也未决定禁用标准智能指针。

只在当前任务需要时收敛相应选择，不一次性要求决定所有远期细节。具体建议与依据见 [ARCHITECTURE.md](ARCHITECTURE.md)。
