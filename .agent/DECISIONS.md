# 当前项目决定

整理：2026-11-09。这里只保留影响后续开发的项目选择；操作与协作规则见 [AGENTS.md](AGENTS.md)。

## 已确认

| 事项 | 当前约定 |
| --- | --- |
| 长期目标 | 建设参考成熟引擎设计、可实际使用和持续演进的个人游戏引擎 |
| 第一阶段 | 用贪吃蛇打通编辑器操作、保存、试玩、简化打包和独立运行；具体可编辑范围尚未确定 |
| 顶层分工 | runtime 提供游戏运行能力；tooling 为独立顶层目录和构建目标；editor 使用二者，正式游戏通常不链接 tooling |
| 配置职责 | XxxConfig 只表达启动参数，由初始化过程消费；运行期修改调用相应子系统接口，不通过修改 Config 驱动，也不要求系统保留完整 Config 副本。需要长期使用的数据由所属系统自行拥有 |
| 当前重点 | 用标准库实现当前阶段的日志记录与多目标分发；TextSink、ConsoleSink、FileSink 已接通，验证范围与剩余边界见 PROJECT。Logger 错误收集留待后续 |
| 日志实现与依赖 | 当前阶段由 Namica 使用原生 C++ 标准库实现，不引入 spdlog；公共接口使用 Namica/标准类型。控制台编码与颜色的必要平台适配保留在内部，具体方案见 ARCHITECTURE |
| 日志职责 | 使用 LogRecord 表达记录，由 LogSink 承担输出；现有整行布局与最低等级迁移至输出端。正文参数格式化与记录构建仍在前端，具体签名见 ARCHITECTURE 草案 |
| 文本输出基类 | ConsoleSink 与 FileSink 继承 TextSink，共享 setLogFmt/setDateFmt 与 formatRecord；颜色、流/文件和刷新策略留在具体 sink。formatRecord 为 const，返回纯文本，不额外添加颜色或行结束符；TextSink 可对外派生，构造函数与析构已导出 |
| 文件输出与共享 | FileSink 持有单个文件，配置支持 Append/Truncate 和逐条刷新开关；显式 flush 独立于开关。Core/App 共用一个默认控制台端及可选文件端，在 Log::init 中注册后再发布 Logger；文件默认关闭，具体默认值与限制见 PROJECT |
| 日志格式化 | 当前实际使用标准库 std::vformat，并非第三方 fmt。继续以标准格式化设施组织文本，不开发通用格式解析器；TextSink 在构造时校验格式，setter 返回 Bool，无效时保留旧值。当前四参数为 `{0}` 时间、`{1}` 等级、`{2}` 来源、`{3}` 正文 |
| Config 构造 | TextSinkConfig/ConsoleSinkConfig 使用便利构造函数，当前不要求保持聚合；以调用处可读性优先，后续如需要纯数据或聚合初始化再改造 |
| 日志日期配置 | 记录保存时间点，文本输出端按配置显示；具体配置位置以当前实现为准（见 PROJECT），不要求结构化接收端转换为文本。公共默认值不等于跨输出端强制同一值 |
| 控制台颜色范围 | 按日志等级对整条日志统一着色，当前不支持分段着色；颜色由 ConsoleSink 添加，不向 LogRecord 写入颜色控制码 |
| 日志线程范围 | 当前阶段暂不开发多线程或异步日志，先采用简单实现；单线程同步调用契约和未来接入位置见 ARCHITECTURE，不把同步输出等同于线程安全 |
| 日志使用前提 | Log 强依赖 Application 初始化；未创建并完成初始化时调用 Log 不受支持，用户不直接调用私有 init。输出资源关闭与失败诊断细节仍待讨论 |
| 日志编译裁剪 | NAMICA_LOG_DEBUG 控制 Trace/Debug 便捷宏；DLL 与调用方分别定义自己的开关，PRIVATE 不向调用方传播是预期行为，调用方开关不能改变已编译的 DLL。关闭分支移除调用与参数求值，当前实现见 PROJECT |
| 异常机制 | 初始化和无法建立有效对象时接受 C++ 异常；正常运行期优先状态/错误码，不以频繁 throw/catch 处理预期失败。底层库异常的转换边界、日志失败状态及不抛保证仍待细化，不等同于全项目关闭异常支持 |
| Sink 错误返回 | write/flush 使用 Bool 表达结果；Logger 负责错误收集，但收集实现明确留待后续。当前不要求扩展错误枚举或建立统一错误框架；返回 Bool 不等于已保证不抛异常 |
| 数学容差 | `NAMICA_TOL` 的位置、名称和值暂时保持，仅在实际涉及容差策略时再讨论 |

阶段目标来源：[项目日记](../doc/life/梦醒再梦.md)。

## 仍需决定

- **日志**：控制台编码适配、文件轮转与周期刷新、编辑器接收和记录有效期契约、初始化失败回滚和关闭协议、后续错误收集与异常边界、未来线程支持、各构建目标的日志开关默认值。
- **游戏制作流程**：最小编辑能力与验收内容、场景和资源数据格式、资源 ID、游戏逻辑接入方式。
- **系统演进**：[Application 应用框架](ARCHITECTURE.md#application-与运行库待讨论)的完整职责与配置、tooling 的库形式、窗口和渲染实验的正式接口、编辑器 UI，以及是否需要 ECS、脚本、反射或热重载。
- **所有权策略**：各系统如何持有和销毁对象、借用引用的有效期，是否需要创建入口、池或句柄；尚未形成全局内存管理方案，也未决定禁用标准智能指针。

只在当前任务需要时收敛相应选择，不一次性要求决定所有远期细节。具体建议与依据见 [ARCHITECTURE.md](ARCHITECTURE.md)。
